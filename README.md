# 栖页 Qiye

**把多个窗口中的网页，整理成随时可以继续的浏览会话。**

栖页 Qiye 是一个本地优先的浏览器标签与书签工作台。在同一页面管理当前打开的标签、原生分组、已保存会话和浏览器书签，通过拖拽完成整理、暂存与收藏。

当前版本 **v1.5.0** · Manifest V3 · 简体中文 / English · 无第三方运行依赖

## 功能介绍

- **多窗口标签管理**：默认展示同一浏览器用户资料中的所有已打开窗口，按窗口与原生组组织；支持窗口全选、定位窗口、激活标签和实时更新。
- **原生标签组**：将选中的标签创建为浏览器分组，拖入已有分组，整组保存、休眠、关闭或解除分组。
- **会话收藏**：保存一组网页以便稍后恢复，支持命名、星标、锁定、克隆、去重、排序，以及批量重新打开。
- **浏览器书签**：直接管理原生书签与文件夹，支持新增、编辑、嵌套文件夹、拖动移动和通过工作台删除后的恢复；内置、托管目录受到保护。
- **休眠与暂存**：休眠后台标签以释放内存，保留标签栏入口；也可先把网址放入暂存区，稍后整理。
- **搜索与备份**：搜索标签、会话、暂存和书签，导入导出收藏、创建工作台快照，并通过回收站恢复误删内容。
- **可配置工作台**：9 个设置分区、77 项偏好，涵盖保存与打开行为、界面显示、标题整理、右键菜单、快捷面板、新标签页和搜索。
- **可选远端同步**：连接自己的 WebDAV 或 GitHub Secret Gist，同步会话、暂存及可选偏好，支持手动同步和按时段自动同步。

### 这几类内容有什么区别？

| 内容 | 用途与行为 |
| --- | --- |
| 当前标签页 | 浏览器中实际打开的网页，按窗口展示；关闭操作会关闭对应页面 |
| 原生标签组 | 当前打开标签的组织方式，成员在列表中只显示一次 |
| 已保存会话 | 留存的一组网址，用于恢复浏览内容；与当前打开的标签独立保存 |
| 浏览器书签 | 浏览器本身的书签和文件夹，修改会直接应用到原生书签 |
| 暂存标签 | 尚未整理的网址，可稍后归入会话或书签 |

当前标签页使用一份完整主列表。浏览会话或书签时，可以显示右侧辅助标签区，方便拖拽整理；该区域可以在设置中关闭。

## 浏览器支持

本项目面向**桌面浏览器**，不同浏览器使用对应构建。

| 浏览器 | 版本要求 | 构建目录 | 当前支持范围 |
| --- | --- | --- | --- |
| Chrome / Edge / Brave / Opera / Vivaldi | Chromium 内核 120+ | `dist/` | 多窗口标签、会话、原生书签；分组和休眠以浏览器实际提供的能力为准 |
| Firefox | 140+ | `dist-firefox/` | 多窗口标签、会话、原生书签、原生分组和休眠；当前提供未签名临时测试构建 |
| Safari（macOS） | 建议 Safari 18+，完整 Xcode | `dist-safari/` | 提供转换源和功能降级适配，尚无可安装应用；原生书签、分组和休眠不可用 |

缺少某项浏览器功能时，相应操作会停用并说明原因。当前已覆盖接口模拟和构建检查，尚未在上述每个浏览器中安装实测。完整说明与官方参考见 [浏览器支持文档](BROWSERS.md)。

## 安装与运行

### 1. 获取源码

安装 **Node.js 20.11 或更高版本**及 Git，然后执行：

```bash
git clone https://github.com/wang-zhengxin/qiye.git
cd qiye
```

也可从仓库下载源码 ZIP 并解压。项目使用 Node.js 内置模块，**无需先运行 `npm install`**。

仓库中的源码 ZIP 与可加载的扩展包不同：源码需要先构建，不能直接在扩展管理页安装。生成的构建目录和安装包不提交到仓库。

### 2. 构建扩展

```bash
npm run build
```

同时生成 `dist/`、`dist-firefox/` 和 `dist-safari/`。每个目录的根部都包含对应的 `manifest.json`。

#### Chrome / Edge / Brave / Opera / Vivaldi

1. 打开对应浏览器的扩展管理页，开启“开发者模式”。
2. 点击“加载已解压的扩展程序”，选择 **`dist/` 文件夹**。
3. 点击栖页扩展图标，或按 `Alt + Shift + T` 打开工作台。

| 浏览器 | 扩展管理页 |
| --- | --- |
| Chrome | `chrome://extensions` |
| Edge | `edge://extensions` |
| Brave | `brave://extensions` |
| Opera | `opera://extensions` |
| Vivaldi | `vivaldi://extensions` |

选择的文件夹内应直接看到 `manifest.json`。如果使用打包生成的 ZIP，请先解压，再选择扩展文件夹；不要直接选择 ZIP 文件、项目根目录或 `artifacts/`。

#### Firefox

1. 打开 `about:debugging#/runtime/this-firefox`。
2. 点击“临时载入附加组件”。
3. 选择 **`dist-firefox/manifest.json`**。

当前构建未经过 Mozilla 签名，用于临时加载测试。重启 Firefox 后需要重新载入；普通 Firefox 的长期安装需要已签名扩展。

#### Safari（macOS）

Safari 源文件不能直接安装。安装完整 Xcode 后，可在源码项目中执行：

```bash
npm run safari:project
```

脚本使用 Apple 的打包工具生成 `safari-project/`。随后在 Xcode 中选择自己的签名团队，构建并运行应用，再到 Safari 设置中启用扩展。签名、应用构建和 Safari 实机验证尚未完成，详见 [Safari 安装说明](INSTALL.md#safarimacos)。

### 只预览页面

```bash
npm run dev
```

访问 [本地演示工作台](http://127.0.0.1:4173/)。演示数据保存在当前浏览器中，与扩展收藏分开；只有安装扩展后才能管理真实标签和书签。

### 生成 ZIP 安装包

```bash
npm run package
```

安装包写入 `artifacts/`，文件名跟随项目版本：

```text
qiye-workspace-chromium-v1.5.0.zip
qiye-workspace-firefox-v1.5.0.zip
qiye-workspace-safari-source-v1.5.0.zip
```

Safari ZIP 是转换源包。更多单独构建命令见下方 [开发与验证](#开发与验证)。

### 更新已有安装

在原项目目录执行：

```bash
git pull --ff-only
npm run build
```

随后在扩展管理页重新加载栖页；Firefox 临时附加组件在调试页重新载入。保留原加载目录，避免因更换目录而被浏览器识别为另一份扩展。完整步骤见 [安装说明](INSTALL.md)。

## 使用指南

### 整理当前标签

进入“当前标签页”，选择“所有窗口”或“当前窗口”。“当前窗口”指工作台所在窗口，选择的范围会自动保存。

勾选标签后，可保存会话、暂存、休眠或关闭；点击“新建分组”将选中的标签创建为浏览器原生组。点击标签切换到对应页面，点击窗口标题区的定位按钮切换到对应窗口。

### 保存与恢复会话

选择网页并点击“保存会话”，或从右侧辅助标签区拖入新建区域，即可留存一组链接。之后在“已保存会话”中打开整组，继续之前的浏览内容。原生分组恢复方式、是否复用已打开网址、是否在新窗口打开等行为均可配置。

默认保存或暂存后保留原标签。开启“保存成功后关闭”时，先写入收藏，再关闭对应页面。**关闭打开的标签**与**删除保存的链接**是不同操作；通过工作台删除的会话或收藏标签会先进入回收站。

### 拖拽规则

| 拖动内容 | 目标 | 结果 |
| --- | --- | --- |
| 打开的标签 | 另一个打开的标签位置 | 调整浏览器顺序，必要时跨窗口或改变分组归属 |
| 打开的标签 | 原生组标题 | 加入该浏览器分组 |
| 打开的标签 / 已保存标签 | 会话 / 暂存区 | 保存网址，或移动已保存的标签 |
| 已保存标签 | 同组或其他会话 | 组内排序或跨会话移动；锁定组受到保护 |
| 标签 / 整个已保存会话 | 书签文件夹 | 保存为书签；整组创建或复用同名子文件夹，源会话保留 |
| 书签 / 书签文件夹 | 另一个书签文件夹 | 移动原生书签或文件夹，禁止移入自身及子目录 |

### 自定义与快捷键

打开“设置与帮助”或顶部“设置”，可搜索配置、切换分区、重置分区和导入导出偏好。修改后点击底部**“保存设置”**才会应用，详细行为见 [配置说明](CONFIGURATION.md)。

| 默认快捷键 | 操作 |
| --- | --- |
| `Alt + Shift + T` | 打开工作台 |
| `Alt + Shift + C` | 保存当前标签 |
| `Alt + Shift + A` | 保存当前窗口的标签 |
| `Alt + Shift + F` | 打开工作台搜索入口 |
| `⌘ / Ctrl + K` | 聚焦工作台内的搜索框，可在搜索配置中修改 |
| `Esc` | 关闭弹窗或菜单，或清除当前搜索 |

浏览器级快捷键需安装扩展，并以浏览器实际分配结果为准。

## 数据、备份与同步

收藏、偏好、快照和回收站保存在当前浏览器的扩展本地存储。不同浏览器、不同用户资料各自独立，默认不连接远端同步服务。

| 方式 | 包含内容与恢复行为 |
| --- | --- |
| 收藏导出 | 会话、暂存、书签及文件夹信息的 JSON；不包含回收站、最近访问、偏好或快照 |
| 收藏导入 | 支持栖页 JSON、含 `groups` / `tabGroups` 与 `tabs` / `tabList` 的兼容 JSON，以及 OneTab 的 `网址 \| 标题` 或制表符文本；添加内容并保留现有收藏 |
| 配置导出 / 导入 | 单独备份偏好，不包含密码或 Token，会保留服务地址等配置；导入后自动同步保持关闭，保存后生效 |
| 工作台快照 | 在本机保留会话、暂存和当时打开的网址；恢复时补回收藏，并将当时打开的标签保存为新会话 |
| WebDAV / Secret Gist | 同步会话、暂存及可选偏好；不包含原生书签、最近访问或凭据 |

导入文件中的书签会进入“导入的浏览器书签”会话，不会直接批量改写浏览器原生书签；书签文件夹树不会由导入自动重建。原生书签的跨设备同步由浏览器自己的同步设置管理。

### 配置远端同步

1. 在“同步配置”中选择 WebDAV 或 GitHub Gist。
2. WebDAV 填写完整 JSON 文件地址，父目录需已存在；Gist 使用有对应权限的 Token，可填写已有 Secret Gist ID。
3. 保存连接配置并授权目标站点访问。Firefox 还会申请可选的数据传输同意。
4. 先测试连接，再手动同步。Gist ID 留空时，第一次手动同步会创建 Secret Gist；生成 ID 后可启用自动同步。

同步支持合并推送、以本地覆盖远端，以及拉取替换本地；覆盖拉取前会创建恢复快照。连接测试只读取，不证明远端写入权限。密码和 Token 单独保存在本机，不进入收藏导出、配置导出或远端偏好。更多规则见 [远端同步配置](CONFIGURATION.md#远端同步)。

## 开发与验证

采用原生 JavaScript ES Modules、CSS 与 Manifest V3，使用浏览器自身的扩展接口；预览、构建、打包和测试均使用 Node.js 内置能力。

| 命令 | 用途 |
| --- | --- |
| `npm run dev` | 启动本地演示页面 |
| `npm test` | 运行自动测试 |
| `npm run build` | 生成全部三个浏览器构建目录 |
| `npm run build:firefox` | 仅构建 Firefox |
| `npm run build:safari` | 仅构建 Safari 转换源 |
| `npm run package` | 重新构建并生成全部三个 ZIP |
| `npm run package:firefox` | 仅构建并打包 Firefox |
| `npm run safari:project` | 使用完整 Xcode 生成 macOS Safari 应用工程 |

当前 **107 项自动测试**覆盖数据移动、锁定保护、回收站恢复、导入校验、去重、多窗口、保存与关闭顺序、配置迁移、同步协议、Firefox 接口和缺少功能时的处理。

界面已通过网页交互验收；真实浏览器扩展接口与同步协议使用模拟 API 测试。尚未逐个浏览器安装实测，也未使用用户的真实 WebDAV / Gist 服务完成端到端验证。


## 常见问题

**为什么网页预览没有显示我的真实标签和书签？**

网页预览使用独立演示数据。构建并在对应浏览器加载扩展，才能读取真实内容。

**为什么 ZIP 无法作为扩展安装？**

Chromium 的“加载已解压的扩展程序”需要文件夹。先解压，确认所选目录内直接包含 `manifest.json`；如果下载的是仓库源码 ZIP，则还需先执行构建。

**打开的标签和已保存会话是不是重复内容？**

两者分别表示当前浏览现场与持久保存的网址。保存会话后即使关闭原标签，仍能从会话恢复；当前标签列表自身只显示一份。

**能同步 Chrome 工具栏中已保存但没有打开的分组吗？**

当前实现管理已打开的原生标签组，暂不支持完整读取 Chrome 工具栏中已保存但未打开的分组。打开该组后，可在工作台中管理并保存为会话。

**“所有窗口”会包含其他浏览器或其他用户资料吗？**

范围是当前扩展所在的浏览器用户资料及其授权可见窗口，不跨其他用户资料或其他浏览器。跨浏览器迁移可使用收藏导入导出，或自行配置远端同步。

**休眠、关闭和删除有什么区别？**

休眠保留浏览器标签，激活后重新加载；关闭会移除实际打开的标签；删除会移除保存的收藏。正在使用的标签不会被休眠，部分特殊标签可能受到浏览器限制。

**“最近访问”是浏览器的完整历史记录吗？**

这里只记录通过栖页打开的链接，不读取完整浏览历史。通过浏览器自带界面删除的书签，也不会进入栖页回收站。
